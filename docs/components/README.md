# Reusable Component Documentation

Create documentation here when a reusable Bright Mind component or subsystem is introduced. One document may cover a coherent component family when that avoids duplication.

Examples that are likely to deserve dedicated documentation later:

- course builder
- course content block system
- activity engine/runtime
- individual complex activity families when their contracts differ materially
- translation editor/workflow UI
- media/resource picker
- publication/status controls
- learning pathway visualization/runtime
- gamification widgets/system contracts

Do not create a Markdown file for trivial styling wrappers or self-explanatory primitives.

## Suggested component document

```text
# Component/System Name

## Purpose
## Where it is used
## Public interface / data contract
## States and behavior
## Permissions (if applicable)
## Localization requirements
## Accessibility requirements
## Analytics/events (if applicable)
## Dependencies
## Testing
## Known constraints / extension points
```

Update the component document when its reusable contract changes.
